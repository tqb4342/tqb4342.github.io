一、4 个项目，从易到难

为了避开「只测一个例子没有说服力」，这次挑了 4 个不同类型：

  1. 3D 程序化城市生成器（纯前端，对标官方 Showcase）
  2. 3D 奥德赛战争视频动画（前端 + 后端全栈，考运镜）
  3. 复刻 Cursor 编辑器（复杂长程全栈，和 Claude Fable 5.1 横评）
  4. 操作 KiCad 电路板布线（Computer Use，不写代码）

下面一个个看。

二、Case 1：3D 程序化城市生成器

思路是对标官方那款城市生成器。我在提示词里只强调了一句：至少包含重庆、上海、西安、深圳、江南五种城市风格，要让人一眼认出是哪座城市。至于参数维度、编辑器布局怎么设计，一个字没提，让 AI 自己发挥。选重庆当主打，是因为层叠立交的复杂地形辨识度最高，最能检验它到底懂不懂城市特色。

实测成品：重庆 · 8D 魔幻山城，右侧是完整的城市生成器控制面板

它拿到任务，先用 Firecrawl 搜了官方 Showcase 的设计，又查了 Three.js 文档，然后一口气写完。约 18 分钟后，7 项自动化测试全过，前端构建成功。

成品第一眼把我镇住了——右侧是完整的控制面板，城市风格、建筑密度、平均高度、地形交通、光照氛围全能调，拖动滑块 3D 场景实时重新生成。五种城市切出来视觉差异极大：上海陆家嘴的超高层天际线、西安的城墙围合和大雁塔、深圳的赛博玻璃幕墙、江南的白墙黛瓦小桥流水……不是简单换颜色，建筑形态、地形高差、地标标注全都跟着变。

这个完成度超出预期了。同样复杂度的活儿，之前用 Claude Fable 5.1 基本半小时起步。

三、Case 2：3D 奥德赛战争视频动画

难度拉高，做一个古希腊特洛伊战争主题的史诗战争动画，而且是前后端全栈项目。这个案例最狠的考点是运镜：整段动画要体现专业运镜手法，不同段落用不同镜头类型，转场自然，战场要有大规模士兵群。怎么实现、后端干嘛，全交给 AI 设计。

特洛伊之围 · 开场：黄昏色调战场、士兵方阵、城墙战舰

它自己搜了特洛伊战争的经典场面和电影运镜，然后设计了一套前后端架构：前端 Three.js 渲染场景 + 镜头动画，后端 Node.js 出两个接口——一个按场景配置生成分镜脚本，一个调 ffmpeg 把帧序列编码成 MP4。约 19 分钟交卷。

成品是一整片黄昏色调的战场，士兵方阵、城墙、战舰群都在，底部还有完整的时间轴播放器，能拖进度、调倍速、全屏，右上角「导出影片」直接对接后端 ffmpeg 接口。整段动画分六章、72 秒叙事，镜头从全景推到近景再拉回收束，轨迹加速度都做了连续性处理。

中间它自己还发现了远景雾气太重、角色脚底悬空几个问题，修了两轮，9 项测试全过。当然也有瑕疵——几处角色穿模，士兵武器偶尔穿过身体，这种再跑一轮大概率能修掉。

特洛伊之围 · 穿模问题：AI 自检没覆盖到的细节

整体看，一句提示词从零做出这种完整度的全栈项目，已经很能打了。

四、Case 3：复刻 Cursor（和 Claude 横评）

这是我最常用的测试案例，让 AI 复刻一个类似 Cursor 的 AI 编程工具。提示词跟之前测 Claude Fable 5.1、Kimi K3 时完全一样，才好横向对比。要求是：克隆 VS Code 开源代码，做一个支持 Editor / Agents 双窗口切换的 Web AI 编程工具，技术栈自由发挥。

它一边搜 Cursor 3 的产品设计，一边用 Git 克隆 VS Code 仓库，约 23 分钟完成第一轮。有意思的是它没照抄「Cursor」这个名字，自己起了个「orbit」，顶部中间就是 Editor / Agents 双窗口切换。

orbit 编辑器：左侧文件树、Monaco 编辑器、面包屑导航、暗色主题全部自带

跟之前几个模型的横向对比很清楚：

模型 复刻结果
Kimi K3 半个多小时跑通核心，界面简陋
Claude Opus 5 还原度高，但跟 VS Code 太像，没自己想法
Claude Fable 5.1 完成度最高，逐文件审阅改动都做了
GPT-6 Astra 有自己的产品想法（自创 orbit 品牌、任务分类、快捷入口），视觉还原度最好，但功能丰富度差 Fable 5.1 一截

这次最惊喜的就是它有产品想法。没照着 Cursor 抄，自己设计了品牌、配色体系、任务管理。但逐文件审阅改动这种功能它没做出来——功能完整度还是 Claude Fable 5.1 更厚实。

同一提示词下 Claude Fable 5.1 的成品：功能最全，但产品想法不如 Astra

五、Case 4：操作 KiCad 电路板布线（翻车了）

前三个都是「写代码」，但 Astra 这次真正主打的是「操作电脑」。官方称它是全球最强电脑操作模型，ScreenSpot-Pro 屏幕理解准确率从上一代 76.9% 拉到 92.7%。官方演示里，它打开 KiCad，把一张原理图变成可生产的 PCB 布线图，元器件怎么摆、铜线怎么走，全由 AI 完成。

官方演示：元器件摆放与铜线布线全部由 AI 完成——这活儿以前是硬件工程师手工拖的，整个电子设计里最费时的环节之一

我装了 KiCad 10，想自己复现一下。结果：约 13 分钟后它没能完成正确的布局布线。它成功打开了项目、进了 PCB 编辑器、导入了网表，原理图一致性检查也过了——说明它确实看懂了原理图和 PCB 的对应关系。但一到画布上点击框选元器件，坐标就经常对不准，没法可靠地拖到指定位置，更别说画铜线了。最终 DRC 报了 12 项违规 + 20 处未连接。

实测结果：流程操作都对，但精细拖拽布线没干成

这个结果让我挺失望。这也侧面解释了官方数据的矛盾：ScreenSpot-Pro 能到 92.7%（看懂屏幕没问题），但 OSWorld 任务完成率只有 72.6%（真把活干完就难多了）。 「看得懂」和「干得成」之间，还隔着精细交互这道坎。

想细看 Computer Use 的能力边界、什么活适合交出去，看这篇 Computer Use 实战。

六、我的几点感受

跑完这 4 个项目，最直观的三条：

  1. 前端审美和产品设计，Astra 比 GPT-5 系列强太多了。 以前 GPT 系列的前端效果老被吐槽，还爱偷懒、功能能省就省。以前用 GPT-5.6 Sol 做出来的足球游戏，球门就是一坨黑色方块：

GPT-5.6 Sol 时代的「能用就行」审美

这次城市生成器连每座城市的地标标注都自己设计了一套「死磕都市特色」，这种用心程度以前看不到。
2. 速度是真的快。 几个项目都 20 分钟左右交卷，比其他同级快近三分之一。
3. 但额度烧得飞快，价格也贵了。 Plus 账号跑 2-3 个项目就能耗光 5 小时额度，Computer Use 更夸张——想长期用至少得开 Pro。

七、所以 Astra 到底值不值得用？

  • 值得用：视觉要求高的前端项目、需要一次性交付的全栈产品——Astra 目前是第一梯队。
  • 没必要：日常大多数办公任务，用这么贵的模型属于杀鸡用牛刀。国产 Kimi、GLM、DeepSeek 够用了，还便宜。

国内想低成本试 Astra 的 Codex，环球巴士 镜像版 28.88 元/月起是最省事的入口——不用海外账号、不用信用卡、支付宝付完就能用，强度下拉直接选 Astra。新用户首单 9 折，**优惠码 Tanqingbo**。重度用户建议上独享（218.88 元/月起），对话数据才沉淀在自己账号里。三种方式的完整对比看 AI 大模型充值教程。

FAQ 常见问题

Q1：Astra 的 Codex 写代码比 Claude 强吗？
各有胜负。前端审美、产品设计、速度 Astra 占优（18-23 分钟交卷），但功能完整度（逐文件审阅改动）差 Claude Fable 5.1 一截。视觉项目选 Astra，稳健功能闭环选 Claude。

Q2：Astra 写代码消耗额度快吗？
快。Plus 跑 2-3 个项目就耗光 5 小时额度，Computer Use 更夸张，长期重度用要上 Pro。日常办公建议国产模型。

Q3：Astra 真能操作电脑吗？
能看懂界面、找到菜单按钮，但精细画布交互会翻车（实测 KiCad 布线 DRC 12 项违规）。看懂屏幕 92.7% 容易，把活干完 72.6% 才难。

Q4：国内怎么用上 Astra 的 Codex？
环球巴士 镜像版 28.88 元/月起，支付宝付款即用，优惠码 Tanqingbo 再 9 折。

Q5：程序员需要恐慌吗？
不用。Astra 把「提示词到能跑的项目」做得很快，但复杂工程仍会穿模、漏功能，需要人把关方案和验收。会用的人效率翻倍，替代还早。
