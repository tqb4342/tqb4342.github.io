DeepSeek Harness 是什么，怎么装，怎么用

DeepSeek 最近开源了一个很有意思的项目，DeepSeek Harness（简称 dsh）。

很多人第一次看到 Harness 这个词，会下意识把它当成另一个聊天客户端——就像之前的 Claude Code。

打开以后才发现，它允许用户拆开 Agent 的组成部分，换模型、加工具、改权限，也可以装插件，甚至自己写一个新插件。

这件事值得好好聊聊。

平时使用 Codex、Claude Code 或 WorkBuddy，我们拿到的通常是一套已经配好的 Agent。

厂商替你选好工具，安排好任务怎样循环，也设好了权限边界。你输入要求，它沿着已有流程完成工作。

DeepSeek Harness 把这些组件开放了出来。

普通用户可以先使用默认配置，愿意继续折腾的人，还可以按照自己的任务组装一套 Agent。

这篇文章从安装开始，带你走一遍界面配置、模式选择、社区插件来源和自制插件。

没有编程经验也能跟着操作。

Harness 到底是什么：模型之外的那一层

简单来说，可以把 Agent 理解成一个能干活的 AI 员工，它大致由两部分组成。

Agent = 大模型 + Harness

大模型负责理解、推理和生成。Harness 负责把模型放进一个可以工作的环境里，给它工具、文件权限、上下文、任务循环、插件和执行记录。

同一个模型放进不同的 Harness，最终表现可能差很多。区别常常出在模型能看到哪些信息，可以调用什么工具，失败以后怎样重试，以及每一步有没有受到权限限制。

所以 DeepSeek Harness 的重点落在怎样组装和管理 Agent。官方给出的概括很直接，Everything is a Plugin，一切皆插件。模型接入、工具、界面和运行能力，都可以通过插件体系组合。

驱动这套插件体系的内核叫 Cordis。这个名字后面还会出现很多次，先记住就好。接下来先把 DeepSeek Harness 跑起来。

安装前准备：Node.js 和 API Key

最省事的官方安装方式需要准备 Node.js 和 DeepSeek API Key。

Node.js 用来运行 DeepSeek Harness。

打开 Node.js 官网，下载适合自己电脑的长期支持版本，按照安装向导完成安装。

API Key 可以到 DeepSeek 开放平台创建。

它相当于模型调用凭证，后续请求会产生 API 费用。

不要把 Key 发进群聊、截图或公开文档，也不要写进准备上传到 GitHub 的文件。

准备完成后，打开终端。

macOS 用户按下 Command + 空格，搜索终端。Windows 用户可以打开 PowerShell 或命令提示符。

输入下面这条官方命令。

npx @deepseek-ai/dsh web

第一次运行会下载依赖，需要等一会儿。启动成功后，终端会打印 Web UI 地址。官方默认地址如下。

http://127.0.0.1:3080

把地址复制到浏览器打开，就能进入 DeepSeek Harness。

如果你已经在用 Codex、Claude Code 或 WorkBuddy，也可以把 DeepSeek Harness 的官方仓库地址发给它，请它检查 Node.js 环境并执行官方启动命令。

这个办法省去了手动输入，安装过程没有发生变化，最后仍然要看到终端给出的本地地址。

官方也提供了从源码运行的方法。

它适合准备开发插件的人，普通用户暂时用不到。按照下面的命令操作前，还需要先安装 pnpm。

git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web

第一次打开：先配置模型和 API Key

进入 Web UI 后，打开设置里的 Models 页面，找到 DeepSeek，填入 API Key 并保存。

官方文档显示，模型配置保存后会在下一次请求生效，不需要重启服务。

接着选择一个本地文件夹作为工作区。

Agent 后续读取和修改的文件都放在这里。

第一次体验时，建议新建一个空文件夹，不要直接选择桌面、文档目录或正在使用的重要项目。

工作区选好以后，再看权限设置。

DeepSeek Harness 会按照当前权限策略决定哪些操作可以直接执行，哪些操作需要先征得同意。

刚上手时，保留审批提示更稳妥。等你看懂它会调用哪些工具，再逐步调整权限。

现在可以发出第一个任务。

请在当前工作区新建一个名为 deepseek-harness.txt 的文档，并在文档中写入 DeepSeek Harness。完成后告诉我文件的保存位置。

如果它能创建这个文档并写入指定内容，模型、工作区和基础写入能力就已经接通了。

四种运行模式怎么选：标准 / PTC / 极简 / 创造

标准模式适合普通任务。整理文件、改文档、分析资料和处理代码，都可以先从这里开始。

PTC 模式适合步骤较多、需要批量执行的任务。批量读取文件、按同一规则处理数据、连续完成一组标准动作，这类任务更适合交给它。

极简模式保留的预设更少，更接近直接观察模型怎样处理任务。它更适合开发者测试，一般用户很少需要。

创造模式把插件组合能力开放出来。你可以添加社区插件，也可以让 Agent 按照开发文档制作新插件。

如果你的目的只是完成日常任务，先用标准模式。等你确实遇到默认能力做不了的事情，再进入创造模式。

Cordis 内核：插件怎样加载、依赖和清理

DeepSeek Harness 把插件看得很重。按照官方架构文档，插件可以注册工具、事件监听和其他服务。

插件卸载时，通过上下文注册的这些内容会自动清理。插件依赖的服务还没准备好，框架会等依赖就绪后再加载它。

这些规则听起来有点抽象，放到图片翻译案例里就容易理解了。

假设我们要做一个图片翻译 Agent。

用户上传一张带有外语文字的图片，Agent 先识别图片里的文字，再把内容翻译成中文，最后将译文保存成文档。

开始制作后，DeepSeek Harness 会先确认最终的交付形式。这里明确告诉它，要做成一个可以安装和复用的插件。

DeepSeek Harness 的官方模型配置文档写得很清楚，DeepSeek 自己的 Chat Completions 路由按文本模型处理，附带图片的请求会在发送前被拒绝。

要完成这个任务，需要接入一个支持图片的模型或视觉插件。

好消息是，这个限制最近被官方补上了——DeepSeek 发布了多模态模型 deepseek-v4-flash-vision-exp，直接在 Harness 里把模型 ID 改成它就能接收图片输入，比挂第三方视觉插件省事，还少一层数据中转。实测效果（网页复刻、报错定位、发票识别）可以看 DeepSeek 多模态实测与接入教程。

视觉插件负责识别图片里的文字，翻译插件把识别结果翻译成中文，导出插件再将译文保存成文档。

Cordis 处理这些插件的加载、依赖和清理，让它们可以在同一个 Agent 里按顺序工作。

如果翻译插件声明自己依赖视觉识别服务，视觉插件还没有准备好时，翻译插件会等待，导出环节也不会提前执行。

这样一来，增加和移除功能不会每次都要求重做整个 Agent。

这次先搭建完整的插件骨架，暂时跳过 OCR 所需的模型配置。

Agent 完成插件骨架后，对话框上方会出现插件的操作界面，这里就是它的使用入口。

DeepSeek Harness 还保留会话和工具执行记录。

用户说了什么、模型怎样响应、调用了哪个工具、工具返回什么结果，都可以顺着记录检查。

插件出错以后，开发者可以从具体步骤开始排查，不必只看最后那句失败提示。

社区插件去哪找，安装前注意什么

开源项目的一大好处，是别人做好的能力可以直接复用。

社区已经有人把散落在 GitHub 上的插件整理成了 DSH 1024Store。

项目页面显示，截至 2026 年 8 月 17 日，它共汇总了 4120 个插件，其中既有开发者通过 PR 主动提交的项目，也有从 GitHub dsh-plugin 话题中自动发现的仓库。

除了列出插件，项目还提供在线市场、搜索入口、公开查询 API 和定期更新目录的流程。

想给 Agent 增加主题、通知、文件处理或外部服务连接时，可以先按插件名称、作者或功能搜索，看看社区里有没有接近的方案，再决定直接安装，还是参考现有代码做一份自己的插件。

这类目录能省下到处翻仓库的时间，也让插件的用途、来源和更新情况更容易比较。

不过，收录数量只能说明选择很多，不能代表每个项目都经过了安全审核。

安装社区插件前要多做一步安全检查。

官方 CLI 对此有专门提示。从 GitHub 安装的插件可能在安装阶段执行 prepare 构建脚本，这一步由 pnpm 在插件所在的 profile 目录中完成，不属于 Agent 任务的沙箱执行流程。

pnpm 默认会拦住这类构建脚本，只有把对应插件明确加入 allowBuilds 后才会继续。

只安装来源可信的插件，最好锁定具体 commit。

来路不明的仓库，即使截图做得很好看，也别急着运行。

DeepSeek Harness 适合谁，值不值得上手

如果你只想装好就用，不愿意处理 Node.js、API Key、插件来源和版本变化，WorkBuddy、Codex 这类成熟的 Agent 产品会省事很多。

如果你已经有一个明确需求，现成 Agent 又缺少某项能力，DeepSeek Harness 会更有意思。你可以安装别人写好的插件，也可以让 Agent 根据官方开发文档替你做一个。模型、工具和界面都能继续调整，做出来的东西也更贴近自己的工作。

它当前的短板同样明显。项目处在开发者预览阶段，界面和配置可能变化。社区插件质量参差不齐，安装外部代码还会带来安全风险。自制插件能生成出来，也需要测试和维护。

所以第一次上手，不要急着组装一个万能 Agent。先完成一个小任务。

安装 DeepSeek Harness，选一个空工作区，跑通模型配置。

随后装一个来源可信的插件，观察它增加了哪些能力。

等这两步稳定，再做一个只解决单一问题的插件。

走完这一遍，你就掌握了 DeepSeek Harness 最基本的使用路径。
